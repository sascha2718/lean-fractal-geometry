# Public release boundary

This repository is intended for public release. Access to another local project
is not permission to publish its contents or identify it here.

- Import material only from an explicitly approved public source and revision,
  or after the owner explicitly approves that exact material for public release.
  A request to consolidate libraries is not release approval for private work.
- A public paper does not establish that its local proof development, unpublished
  extensions, working notes, or uncommitted changes are approved for release.
- Apply this boundary to proofs, statements, documentation, author lists, paper
  titles, source paths, repository URLs, provenance, Git history, and CI output.
- Do not submit unpublished titles, statements, or other private project details
  to web searches or external reference services.
- Keep uncleared material outside the public repository and its history. When
  release status is unclear, continue with cleared material and ask the owner.
- Before publication, review both the files and all history being pushed.

For literature-only extractions, use independent mathematical statements and
neutral module names. Remove private application assumptions, source identifiers,
manuscript labels and project cross-references from all distributed files.
Do not record excluded private projects in public provenance or exclusion lists.
